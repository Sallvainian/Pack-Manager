# Spine Pair Review — Pack-Manager

## Overall verdict

Mechanically this is one of the denser spine pairs I have walked: 22/22/22 exact component-name parity across `DESIGN.md` frontmatter, `DESIGN.md`.Components and `EXPERIENCE.md`.Component Patterns; 22 color tokens all carrying hex and all already adopted into `src/styles/theme.css` under D35; all six Key Flows carrying a named protagonist, numbered steps, a climax beat and a failure path; all four mockups linked inline with no orphans. The contract fails on inheritance, not on content. Seven of the eleven `sources:` paths across the two files do not exist, and the three that matter most were **deliberately** retired by `docs/DECISIONS.md` D33 — so a downstream consumer following the frontmatter either finds nothing or lands in `_bmad-output/archive/`, which `epics.md:20` marks "NOT authoritative". Body prose compounds this by naming the retired PRD as the live authority for exact commands, execution and safety.

The second-order damage is a state layer organized by lifecycle phase instead of by surface, which lets `offline`, `no Managers` and `zero-count` fall through despite `DESIGN.md` requiring all three, and a live architecture contradiction (`ARCHITECTURE-SPINE.md:1050`) the pair does not resolve.

Because the PRD is gone, I derived the live requirement set from `epics.md` — the AJ identifiers (`epics.md:148-153`) and the 28 Epic UX-PB stories (`grep -c "^### Story UX-PB"` = 28).

## 2. Token completeness — adequate

Extracted all frontmatter tokens (`sed -n '15,36p' DESIGN.md | grep -c ': "#'` = 22 colors; 22 rows in the prose Colors table) and every `{path.to.token}` reference in both files (`grep -on "{[a-zA-Z][a-zA-Z0-9_.-]*\.[a-zA-Z][a-zA-Z0-9_.-]*}"`): exactly two, both in `EXPERIENCE.md:318`, both resolving — `{colors.focusRing}` → `DESIGN.md:23` and `{colors.borderStrong}` → `DESIGN.md:22`. No color token is missing hex. All 22 landed in `src/styles/theme.css` under D35, which is the strongest possible evidence the color layer is extractable.

### Findings

- **high** One health-scale band names no token and no hex. `DESIGN.md:138 "- 80–99% current: interpolate through yellow-green while maintaining contrast"` — the other three bands name `danger`, `warning`, `success`. There is no yellow-green token in the frontmatter and none in `theme.css` (`grep -c "^\s*--color-"` = 25, none yellow-green). It also sits in tension with the same file's hard rule at `DESIGN.md:246 "Do not use a gradient inside the Package Health Meter, fabricate progress percentages, or use color as the only signal."` — "interpolate" is exactly the gradient the Don't forbids, applied to fill color rather than fill geometry. A builder implementing Health Meter at 80–99% cannot resolve a value. *Fix:* define one token (e.g. `healthNear: '#…'`) with hex, or collapse 80–99% into `warning`.
- **high** No non-text contrast target is stated, and the selection tokens fall below the 3:1 WCAG 1.4.11 floor. `EXPERIENCE.md:317 "- All ordinary text and controls target at least 4.5:1 contrast; large display text targets at least 3:1."` is the only stated figure; selection is carried by `DESIGN.md:118 "| \`borderStrong\`  | \`#465773\` | Selected or emphasized boundaries"` and `DESIGN.md:125 "| \`accentSubtle\`  | \`#172A46\` | Selected-row or active-destination wash"`. Computed from those hex values (WCAG relative-luminance formula, script in scratchpad `c.py`): `borderStrong` vs `surface` = 2.33:1, vs `overlay` = 1.97:1; `accentSubtle` vs `surface` = 1.18:1, vs `raised` = 1.08:1. Every *text* pair passes 4.5:1 — the gap is entirely non-text. This matters more than usual here because `ARCHITECTURE-SPINE.md:328 "**Automated 4.5:1 text contrast does not exist**"` and the check is by eye on the release checklist, so the spine is the only reference the checker has. *Fix:* state a non-text/UI-boundary target (3:1) in `DESIGN.md` § Colors and either darken/lighten `borderStrong` or require selection to also carry a non-color cue.
- **medium** Line heights are load-bearing and exist only as prose. `DESIGN.md:151 "| Body                       |        13px / 19px |      400–550 | Default dense desktop copy"` — eight roles carry a line height in the Typography table, and the `typography:` frontmatter (`DESIGN.md:48-56`) defines `fontSize` only, no `lineHeight`. The spec allows it: `design-md-spec.md:16 "Each value: an object with any subset of \`fontFamily\`, \`fontSize\`, \`fontWeight\`, \`lineHeight\`, \`letterSpacing\`."` *Fix:* add `lineHeight` beside each `fontSize`, or restructure per the spec's role-keyed shape.
- **medium** Typography role names in prose never match the frontmatter keys. Frontmatter keys are `micro, caption, bodySmall, body, label, headingSmall, heading, summaryValue` (`DESIGN.md:49-56`); the prose table's roles are `Window title / micro label`, `Compact metadata`, `Body`, `Control label`, `Section heading`, `Page heading`, `System summary value`, `Commands / versions` (`DESIGN.md:149-156`). The mapping is inferable only by matching px values. Weights are worse — `DESIGN.md:150 "|        12px / 17px |      400–650 |"` is a range, and `fontWeight` defines five discrete tokens (`DESIGN.md:42-47`). *Fix:* put the token name in a column of the Typography table.
- **medium** The `components:` frontmatter carries prose, not tokens. `design-md-spec.md:19 "| \`components\` | object | Component-name → object of component tokens mapped to values or \`{path.to.token}\` references. |"`; the file has `DESIGN.md:73 "  button: Blue primary, neutral secondary, text, and danger variants with visible focus and honest disabled states."` — a string. All 22 entries follow that shape, so the machine-readable component layer is empty and duplicates the prose table. *Fix:* either give each component a token object (`background: '{colors.accent}'`, `radius: '{rounded.control}'`) or drop the block, since the Components table already carries the contract.
- **low** `DESIGN.md` prose uses zero `{path.to.token}` references (`grep -c "{colors\." DESIGN.md` = 0), against `design-md-spec.md:36 "\`{path.to.token}\` used in prose and inside component objects to reference frontmatter tokens."` Backticked bare names (`` `focusRing` ``, `` `inset` ``) are unambiguous here, so this is cosmetic. *Fix:* optional; adopt the brace form for grep-ability.

## 4. State coverage — thin

Walked every IA surface in `EXPERIENCE.md` § Primary navigation (Dashboard, Managers, Activity, History, Settings) and § Surface map (9 rows), then checked each against `EXPERIENCE.md` § State Patterns. The state layer is organized by *lifecycle phase* — Loading and refresh, Draft Upgrade Plan, Confirmation, Live Activity, Results and recovery, History and replay, Settings — not by surface, which is why the misses cluster on surfaces that have no lifecycle phase of their own (Dashboard-at-zero, History-at-zero, filtered grid). Both shipped examples use a `State | Surface | Treatment` table for exactly this reason.

### Findings

- **high** `offline` is required by `DESIGN.md` and specified nowhere in `EXPERIENCE.md`. `DESIGN.md:222 "| **State Panel**               | Purpose-specific title, explanation, and one safe next action where available. | Loading, empty, offline, no Managers, no active upgrade, interrupted, fatal |"`; `grep -in "offline" EXPERIENCE.md` returns nothing. A package manager is a network-dependent product; a builder has a required visual state with no behavioral rule. *Fix:* add an offline row to State Patterns saying what degrades (refresh, app-update check) and what still works (draft editing, History, replay).
- **high** The zero-Managers case is required twice in `DESIGN.md` and covered nowhere. `DESIGN.md:205` gives System Summary Card the required state `no Managers`, and `DESIGN.md:222` gives State Panel the same. `EXPERIENCE.md:172 "- A normally absent Manager is not an error. - **medium** `fatal` / unrecoverable is required and unspecified. `DESIGN.md:93 "  state-panel: Purpose-built empty, loading, offline, interrupted, or unrecoverable state."` and `DESIGN.md:222` lists `fatal`. `EXPERIENCE.md` covers `Interrupted` (line 221) but has no unrecoverable path. *Fix:* one bullet, or drop `fatal` from the required states.
- **medium** History has no empty state and no no-results state. `EXPERIENCE.md:239 "- Search and filters operate on plan time, result, Manager, Package, and relevant text."` — nothing states what History shows before a first plan is ever confirmed, or when a search matches nothing. - **medium** The pair does not resolve a contradiction the architecture spine has already logged against it. `ARCHITECTURE-SPINE.md:1050 "\`docs/SPEC.md\` F5 has Esc \"clears the transient selection\", while \`EXPERIENCE.md\` has selection \"immediately adds/removes Upgrade Plan membership\". … Under the \`EXPERIENCE.md\` reading, Esc would mass-write AD-23 tombstones; under the \`SPEC.md\` reading it writes nothing.
