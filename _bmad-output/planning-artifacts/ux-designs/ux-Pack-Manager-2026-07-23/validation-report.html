Pack-Manager — UX Design Validation Report

_bmad-output/planning-artifacts/ux-designs/ux-Pack-Manager-2026-07-23/

Mechanically these are among the denser spine pairs in the repo: exact 22/22/22 component parity across DESIGN.md frontmatter, DESIGN.md#Components and EXPERIENCE.md#Component Patterns; all 22 colour tokens carry hex; all six flows carry a named protagonist, numbered steps and a climax; all four mockups are linked with no orphans; both files sit in canonical section order. Against the code they are now in good standing — D35 adopted all 22 colours into src/styles/theme.css with zero value mismatches, and the focus migration the spines asked for landed at 31 sites.

They fail on inheritance. Seven of the eleven sources: paths across the two files do not exist, and the three that matter were deliberately retired by docs/DECISIONS.md D33. This is not bookkeeping: EXPERIENCE.md:27 still delegates the authority for exact commands, execution, persistence and safety to that retired PRD, so the most consequential UX in the product currently points at nothing.

Beyond provenance, the pair carries a small number of genuine build-blockers — a sidecar that two sections require to hold two different things at once, an irreversible-run stop control with two different labels in one file, a Verifying state that is normative in one spine and absent from the other, and a Retry behaviour that contradicts epics.md. An Update run is needed. One item — transient selection — is an owner decision, not a doc edit.

2. Token completeness

adequate

All 22 colour tokens carry hex and are adopted verbatim in code. Gaps are in non-text contrast targets and one undefined health-meter band.

high

Non-text contrast has no stated target and the selection tokens fall below 3:1

EXPERIENCE.md:318 · DESIGN.md:122
Computed from the spine’s own hex: borderStrong vs surface = 2.33:1, vs overlay = 1.97:1; accentSubtle vs surface = 1.18:1 — all below WCAG 1.4.11’s 3:1 floor, with no non-text target stated anywhere. EXPERIENCE.md:318 permits borderStrong to indicate selection. All text pairs pass 4.5:1, including DESIGN.md:122’s textMuted claim (4.99:1 through overlay — true, 0.49 of margin). ARCHITECTURE-SPINE.md:328 confirms automated contrast does not exist, so the by-eye checker has no reference values.
Fix: state a 3:1 non-text target and give the by-eye check a table of computed values.
medium

Health-meter 80–99% band has no colour value

DESIGN.md:138
“80–99% current: interpolate through yellow-green while maintaining contrast” names no token and no hex, while :134 requires “one solid fill color—not a gradient fill” and :246 forbids “a gradient inside the Package Health Meter”. Implementable only by invention.
Fix: name a token for the band, or collapse 80–99% into success/warning.
medium

Radius tokens diverge and most are undefined in code

DESIGN.md:57-63 · src/styles/theme.css:46
DESIGN.md declares 6 radius values; theme.css defines 2, and both shared names disagree — --radius-card: 10px vs card: 13px, --radius-control: 6px vs control: 7px. Dialogs borrow rounded-card.
Fix: reconcile in the same direction D35 took the colours — adopt the spine’s values, or record a decision changing them.

Usability review

review-usability.md

The prior review is essentially closed (11 of 12 resolved) and the spines are now strong on the draft lifecycle. They specify the execution lifecycle thinly, and three defects block the build.

critical

The single Upgrade Sidecar has two mutually exclusive required occupants

EXPERIENCE.md:62, :100-101, :179
:62 commits the sidecar to Results “until Done”; :100-101 permits “A user may continue reviewing a draft, but it cannot be confirmed until the active attempt is terminal”; :179 opens the sidecar unconditionally on “First eligible addition”. Adding an item while Results is pending has no defined outcome. epics.md:782 restates the collision rather than resolving it, so UX-PB.1b and UX-PB.3a cannot both be built as written.
Fix: decide precedence — stacked regions, a Results dismissal requirement, or a draft-defers rule.
critical

The irreversible-run stop control has two labels in one document

EXPERIENCE.md:155 vs :216, :427
:155 “Stalled rows expose exactly Keep waiting, Copy command, and Cancel” against :216 and :427 “exactly … Cancel plan”. The file’s own glossary at :110 reserves the generic form for “closing a dialog or retry-scope editor without mutating running work”. DESIGN.md never contains the string Cancel plan.
Fix: :155 → Cancel plan; add the label to DESIGN.md’s Activity Operation Row.
high

The 900×600 minimum does not fit the specified content

DESIGN.md:171 · mockups/manager-workspace.html
Arithmetic from the authoritative mockup’s own CSS: sidebar 190 + padding 32 + gap 14 + sidecar 370 leaves 294px for a .grid-row declaring min-width: 560px, pushing Version, Status and Source behind horizontal scroll — contradicting DESIGN.md:171’s promise to “preserve the sidebar, the primary action, status words, and version evidence”. The high-zoom rule cannot rescue it: its 720px trigger measures the window (900), not the pane.
Fix: raise the minimum, narrow the sidecar, or make the grid drop columns before scrolling.

Accessibility review

review-accessibility.md

All 6 prior findings are closed in spine text and D35 implemented the focus half correctly. What remains is a different class: the spines predate the ring→outline migration and never record the constraint that motivated it. No critical issues on the spine side.

high

Neither spine records the WebKit native-appearance constraint

DESIGN.md:119 · EXPERIENCE.md:318
grep -ci 'box-shadow' → 0 and WebKit → 0 in both files; DESIGN.md:119 still calls the token a “ring”. The reason lives only in docs/DECISIONS.md D35 and AD-27. A story satisfying EXPERIENCE.md:318 “at least 2px wide” with ring-2 reships the exact defect D35 closed at 31 sites — invisible to grep, since it returns as a different class name.
Fix: record “drawn with outline, never box-shadow/ring-*” in the Accessibility Floor, and require outline-offset.
high

Checkbox target size contradicts the Accessibility Floor, and code takes the smaller value

DESIGN.md:203 vs EXPERIENCE.md:327
DESIGN.md:203 “16–18px aligned control” against EXPERIENCE.md:327 “Hit targets are at least 28 × 28px for compact desktop controls”. Code lands on the smaller: src/components/manager/PackageRow.tsx:98 is h-4 w-4 (16px). This is the control that governs plan membership.
Fix: reconcile the two numbers, then give the control a ≥28px hit area independent of its painted box.
high

Focus destination undefined when the draft sidecar closes

EXPERIENCE.md:181 · matrix :294-302
:181 “Removing the final item closes the sidecar” names no focus destination, and the nine-row Focus transitions matrix has no such row — asymmetric, since the opening case is covered at :179. Pressing the last Remove from the keyboard drops focus to <body>.
Fix: add a matrix row returning focus to the source row’s checkbox or the plan heading.
low

Reduced motion freezes the indeterminate spinner

src/styles/theme.css:61-66 · Spinner.tsx:13
theme.css kills all animation; Spinner.tsx:13 is animate-spin. EXPERIENCE.md:310 asks to “remove nonessential animation”, but a running indicator is essential state. The automated test asserts only an idle button.
Fix: exempt progress indicators, or specify a non-animated running affordance.

Code-consistency review — defects that belong in code, not the spines

review-code-consistency.md

The colour layer is in exact lockstep — all 22 colours adopted with 0 missing and 0 value mismatches — and the focus migration is real and CI-guarded. But two shipped defects violate the spines, and in both cases the spine is right and the code is stale.

critical

Shipped text-on-fill contrast failures; the tokens that prevent them have zero consumers

Button.tsx:7, :11 · UpdateStatusItem.tsx:63
primary: "bg-accent text-white …" and danger: "bg-danger text-white …". Computed: white on accent #65A7FF = 2.46:1, on hover #7DB3FF = 2.15:1, on danger #FF8793 = 2.30:1 — all fail 4.5:1 and 3:1 against EXPERIENCE.md:317. grep -rn 'on-accent\|on-success' src/ matches only theme.css. Using the spine’s own tokens gives 7.74:1 and 12.15:1. D35 adopted the palette but not the on-fill pairs, and contrast is by-eye at release.
Fix: code change — text-on-accent / text-on-success in place of text-white. No spec change needed.
high

Explanatory-disabled checkboxes use native disabled

PackageRow.tsx:92 · EXPERIENCE.md:326
EXPERIENCE.md:326 requires aria-disabled="true" and explicitly forbids native disabled; the code is disabled={checkboxDisabled} and grep -rn aria-disabled src/ | wc -l → 0. The pinned-Package explanation is keyboard-unreachable today.
Fix: code change — swap to aria-disabled with inert activation, per the spine.
medium

Sidebar width

DESIGN.md:166 · Sidebar.tsx:63
DESIGN.md:166 “A 190px left sidebar at ordinary zoom” vs w-60 (240px) in code, and docs/SPEC.md:227. The 900×600 arithmetic above assumes 190.
Fix: pick one and propagate; it changes the minimum-width math.
