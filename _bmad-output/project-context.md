# Project Context for AI Agents

## Technology Stack & Versions

- One macOS Tauri application; the React interface and Rust core are internal layers of the same bundle. There is no HTTP API or database.
- Never quote an app version from this or any document — it moves on every release merge (1.0.0 → 1.0.1 in `8a4cf6a`). The version the bundle ships with is `src-tauri/tauri.conf.json`; the version Rust reports in diagnostics is `env!("CARGO_PKG_VERSION")` from `src-tauri/Cargo.toml`. release-please keeps those in lockstep with `package.json`, `package-lock.json`, `src-tauri/Cargo.lock`, and `.release-please-manifest.json`.
- Rust 2021, Tauri crate 2.11.5, Tokio 1.53.1, Tauri opener 2.5.4, and updater 2.10.1. `Cargo.toml` declares tokio with `rt-multi-thread`, `process`, `io-util`, `time`, `sync`, `macros`, plus `test-util` as a dev-dependency for paused-time tests. Other tokio APIs still compile because `tauri` unifies extra features in — declare any feature this crate actually depends on rather than relying on that.
- Tauri JavaScript API 2.11.1 and CLI 2.11.4.
- React and React DOM 19.2.8, TypeScript 7.0.2 (the native port, not 5.x — tilde-pinned `~7.0.2`, patch-only, unlike every other caret-ranged dependency), and Vite 8.1.5 with `@vitejs/plugin-react` 6.0.4.
- Tailwind CSS 4.3.3 (v4 via the `@tailwindcss/vite` plugin; there is no `tailwind.config.js`), Zustand 5.0.14, and TanStack React Virtual 3.14.8.
- Vitest 4.1.10, React Testing Library 16.3.2, `@testing-library/jest-dom` 7.0.0, jsdom 29.1.1, and Cargo tests for unit/integration.
- Playwright 1.61.1 (Chromium + WebKit) with `@faker-js/faker` 10.5.0 for browser end-to-end tests, run separately from the Vitest suite.
- `package.json` declares loose ranges (`"@tauri-apps/api": "^2"`), so a manifest range is never the resolved version — read `package-lock.json` / `Cargo.lock`.
- Node is pinned to 24 in `.nvmrc`. `test.yml` reads it via `node-version-file`, but `node-version: 24` is hardcoded three more times — **twice in `ci.yml`** (the `web` job at :57 and `build-smoke` at :76) and once in `release.yml` (:80) — so a bump has four pin sites and editing only one of `ci.yml`'s two leaves the other job behind. Count with `grep -rn "node-version: 24" .github/workflows/` before bumping. There is no `rust-toolchain.toml`; both lanes install stable, but the action reference form differs per workflow (`ci.yml` floats `dtolnay/rust-toolchain@stable`, `release.yml` SHA-pins the same action).
- The macOS runner label is pinned in exactly three places and they are one set: `ci.yml` `rust` (:28), `ci.yml` `build-smoke` (:70), and `release.yml` `build` (:63) — all `macos-15` since D34 retired the `macos-14` pin ahead of GitHub's 2026-11-02 unsupported date. D20 still governs: a **named stable** image, never a beta one and **never `macos-latest`**, which D34 rejected because a floating label would move the signing and notarization environment without a commit. Change all three or none.
- Minimum supported macOS is 15.0 (`src-tauri/tauri.conf.json` `bundle.macOS.minimumSystemVersion`, D31). Do not lower or remove it, and do not assume APIs newer than macOS 15. D34 closed D31's open `notarytool` question: on `macos-15` the build SDK is no longer behind the declared floor, so the mismatch that question was about no longer exists.

## Critical Implementation Rules

### Language-Specific Rules

- Keep TypeScript strict and no-emit. Unused locals/parameters and switch fallthrough are errors. Use relative imports and `import type` for type-only imports; no path aliases are configured in any tsconfig or Vite/Vitest config.
- `npm run build` is `tsc && vite build`, so a full typecheck gates the bundle. A stubbed parameter or unused local fails the production build, not just the typecheck job — scaffolding placeholders cannot be committed.
- Three disjoint tsconfigs partition the tree and none of them extends another's `include`. Root `tsconfig.json` includes only `["src"]`; `tsconfig.node.json` covers only `vite.config.ts` and `vitest.config.ts`; `tests/tsconfig.json` covers the Playwright tree and is reached only by `npm run test:e2e:typecheck`. So `npx tsc --noEmit` and `npm run build` typecheck **nothing** under `tests/`, and a type error there is invisible until the separate e2e typecheck runs.
- Every IPC enum declares its wire casing explicitly with `#[serde(rename_all = ...)]` — bare serde would emit the PascalCase variant name. Exactly five use `lowercase`: `ManagerId`, `ManagedBy`, `ManagerStatus`, `HealthSeverity`, `StreamKind`. Everything else uses `camelCase`, including `UpdateCheckTrigger`, whose variants are single words — so single-word variants do **not** imply `lowercase`; read the attribute, never infer it. The stable `ErrorCode` uses `snake_case`. Never omit the attribute on a new IPC enum, and preserve each existing wire spelling. `Option<T>` with `skip_serializing_if` maps to an optional TypeScript field, a plain serialized option maps to `T | null`, and `#[serde(skip)]` data is backend-only with no TypeScript mirror.
- The two internally-tagged struct-variant enums, `SelfUpdateRoute` (`ipc.rs:194`) and `AppUpdateState` (`ipc.rs:498`), each need a **second** attribute — `rename_all_fields = "camelCase"` alongside `tag = "kind"` and `rename_all`. `rename_all` renames the variants; it does not touch the fields inside them. Omit `rename_all_fields` on a new struct-variant enum and the payload silently ships snake_case field names.
- Define TypeScript wire enums as `as const` arrays with derived unions and runtime guards. Preserve stable `IpcError` codes and context fields.
- Route caught `unknown` frontend errors through `describeError` — Tauri rejects a failed `invoke()` with a plain serialized object that `String(e)` collapses to `"[object Object]"`. The result goes to `logFrontendEvent("error", ...)`, which invokes `log_frontend_event` into the Rust structured log: there are **zero** `console.*` calls in `src/`, and adding one puts the diagnostic somewhere no bug report will ever include it. User-facing display copy comes from `errorCopy(err)` instead; the two are not interchangeable.
- Package IDs are `${kind}:${name}` and split on the first colon only, so a nested name like `tool:npm:prettier` round-trips. mas is the one exception: its id segment is the numeric App Store id (`app:497799835`), not the display name, because `mas upgrade` takes the numeric id — never build a mas argv or routing key from `name`. Preserve manager-supplied version strings verbatim and represent unknown versions as `null`.
- Do not hold `std::sync` guards across `.await`, and do not use `unwrap()` on fallible user-reachable paths.
- An async mutation of canonical state brackets its `.await` with the `StateUpdateLease` (`state.rs:348`), not with a held guard: `begin_state_update()` reserves the epoch and bumps the revision before the probe, `finish_state_update()` publishes coherently after. That counter is what `state_update_in_progress()` reports and what plan execution fails closed against, so a mutation that skips the lease lets a plan admit against half-updated state.
- The coordinator-first lock order is scoped to **canonical plan construction**, not to every read. `current_plan_state` (`commands.rs:78`) collects `detection`, `registry`, `queue.records()`, `settings`, and `tool_env` in one epoch and its doc comment states the contract: "Caller must hold `state.plan_coordinator`". Taking those five without it yields a mixed-time collection — exactly the drift the plan-staleness machinery exists to prevent. A read that is not building a plan may legitimately skip the coordinator; `refuse_app_update_while_busy` at `commands.rs:810` reads `queue.records()` alone and correctly does not take it. Hold the coordinator when the values must agree with each other; do not cargo-cult it onto single-value reads.

### Framework-Specific Rules

- `src/lib/ipc/bridge.ts` is the only frontend module that imports Tauri APIs, and it re-exports exactly `invoke`, `listen`, and `UnlistenFn`. The rule is convention-only — no lint enforces it. Components use typed wrappers from `client.ts`; `events.ts` owns native event subscriptions.
- Keep payloads for argument-taking commands wrapped as `{ args: ... }`; no-argument commands omit the payload entirely rather than sending an empty object. Any IPC change must update Rust models, TypeScript mirrors/guards, and `dev/fixtures/ipc/*.json` together.
- Subscribe to native events before `get_state` hydration so startup detection cannot be missed, and never clobber a real detection report (non-empty `managers`) with the pre-detection placeholder. Preserve the `Promise.allSettled` rollback — `Promise.all` would trap the already-registered unlisten functions inside the rejected aggregate and leak handlers for the process lifetime. Clean up every listener.
- The launch refresh must go through `scheduleLaunchRefresh()`, never fire inline from bootstrap: `refresh_all` re-runs detection itself, so calling it directly at launch races the startup detection with a second concurrent pass. It runs immediately only when a real detection is already hydrated; otherwise it arms a one-shot the first real `detection:updated` consumes.
- Use narrow Zustand selectors in components and the specific hook's static accessor (for example, `useUiStore.getState()`) outside React. The deliberate exception is derived state that needs the whole operations store (`ManagerPane`, `deriveManagerPhase`), which subscribes to `useOperationsStore()` wholesale — do not "fix" those into selectors returning fresh arrays or objects, because Zustand 5 has no default shallow equality and that is a re-render loop. Replace objects/Sets immutably; put cross-store derived state in `src/store/index.ts`. Per-manager phase is derived (`error > refreshing > busy > idle`), never stored.
- Operation side effects — completion toasts and drawer auto-open — fire only on a genuine status transition of an already-known operation. First sightings (records hydrated from `get_state`, or an op's initial `queued` event) must fire nothing, so rehydration stays silent and the drawer never pops on launch. Refresh operations never toast on success and never auto-open the drawer.
- Keep feature components under `src/components/<feature>/`, shared controls under `components/primitives/`, and navigation in the existing discriminated `ActiveView` state rather than adding a router. `DialogHost` is the single mount point for modal surfaces and shows one dialog at a time off `ui.dialog.kind`.
- Hooks must precede early returns. Effects must clean up subscriptions/timers and declare correct dependencies. Guard async dialog continuations with mounted/latest-request refs so dismissal cannot trigger stale rebuilds or state writes.
- Design tokens live in `src/styles/theme.css`; the product is dark-only. The values are the approved "Aurora Control Deck" palette from the 2026-07-23 UX design (`DESIGN.md` `colors:`), adopted in D35 — they are no longer the foundation stubs that predated the design. Do not add hardcoded hex colors elsewhere. Color states need text or icon equivalents, status chips must not wrap (`whitespace-nowrap` and `shrink-0` are baked into the `Chip` base classes), and the global `prefers-reduced-motion` reset must remain intact. The three `--color-sev-*` tokens deliberately mirror danger/warning/success and must keep mirroring them, so one table row cannot render two palettes.
- **Focus is drawn as a real 2px `outline` in `--color-focus-ring` with `outline-offset` — never `ring-*`, and `outline-none` is never added to a focusable element** (Tailwind v4's `outline-none` genuinely sets `outline-style: none`; the v3 no-op was renamed `outline-hidden`). All 93 `focus-visible:outline-*` sites in `src/` follow this and there are zero `focus-visible:ring` and zero `outline-none`. Focus must never be `--color-accent`: `EXPERIENCE.md` requires a separate indicator so focused and selected stay distinguishable. Exactly one `ring-accent` survives on purpose — `PackageRow.tsx:85` `ring-2 ring-inset ring-accent`, the cross-manager navigation highlight, which has no `focus-visible:` prefix and is pinned by `managerPane.test.tsx:114,118`. Do not repoint or remove it, and do not read it as license to use `ring-*` for focus.
- Ink on a bright fill is a token, never `text-white`. `--color-on-accent` (`#07101D`) and `--color-on-success` (`#07140D`) exist for exactly this and D35 added them for exactly this reason. Measured on `--color-accent`, white gives 2.46:1 and fails the 4.5:1 floor while `--color-on-accent` passes; on `--color-danger` white gives 2.30:1 against 8.30:1. (This correction is currently an uncommitted working-tree change to `Button.tsx` and `UpdateStatusItem.tsx`.)
- Editing a `theme.css` token value is a coordinated change: `tests/e2e/browser-style-contract.spec.ts` pins several tokens as literal `rgb(...)` strings (`rgb(9, 12, 19)` for `--color-bg-base`, `rgb(244, 247, 251)` for `--color-text-primary` and `--color-focus-ring`, `rgb(23, 42, 70)` for `--color-accent-subtle`). A token edit that does not move the spec in the same commit leaves `npm test`, `tsc`, and `npm run build` all green and turns only the separate Playwright lane red.
- Window dragging depends on three unguarded, uncoupled pieces (03e03fa) — break any one and the title bar silently stops dragging with no failing test. `titleBarStyle: "Overlay"` puts the webview under the title bar, so only `data-tauri-drag-region` elements move the window; the ACL must grant `core:window:allow-start-dragging` or the region invokes a command that is denied; **both** top-level columns reserve the same 38px strip (`Sidebar.tsx` `pt-[38px]`, `AppLayout.tsx` `h-[38px]`) and nothing links the two literals; and a region with children needs `data-tauri-drag-region="deep"`, because a bare attribute matches only `composedPath[0]` and child spans swallow the mousedown.
- Two virtualization thresholds exist and are deliberately different: the package table virtualizes above 100 rows (`PackageTable.tsx`), the live log above 200 lines (`LiveLogView.tsx`). The 5,000-line per-operation cap is `LOG_CAP` in `src/store/operations.ts` — enforced in the store, not the view, with dropped lines counted into `overflow` so the view can show its "earlier output in log file" banner. Do not unify or relocate these.
- The dev server port 1420 is duplicated across `vite.config.ts` (`strictPort: true`), `src-tauri/tauri.conf.json` (`devUrl`), and `playwright.config.ts`. Changing one without the others breaks `tauri dev` or the e2e lane.

### Testing Rules

- Default suites must be deterministic and offline: processes use `CommandRunner`/`FakeRunner`, events use `EventSink`/`VecSink`, frontend IPC uses `bridge.ts`/`fakeIpc`, and time uses paused Tokio or fake timers. Do not add real processes, network calls, sleeps, or machine state to default tests.
- Keep parser tests grounded in committed captures under `dev/fixtures/`. Never invent an unlabeled fixture; synthetic inputs require `_synthetic` plus their source and retirement condition. A `_synthetic` fixture proves crash resistance and expected shape only — it can never establish real-format correctness. New captures come from `dev/capture-fixtures.sh`, which date-stamps every file and refuses to clobber an existing one (delete by hand to re-take); network-dependent `outdated` probes need `PM_CAPTURE_ONLINE=1`.
- For intentional IPC changes, regenerate fixtures with `PM_UPDATE_CONTRACT=1 cargo test ipc_contract` from `src-tauri/`, update `src/lib/ipc/types.ts`, then run both language suites. Never set `PM_UPDATE_CONTRACT` in a verification run — it makes the contract test overwrite the fixtures instead of asserting. The TypeScript half asserts the fixture set exactly equals its guard map, so editing either side alone breaks that side by design.
- Focused tests may be colocated; cross-feature frontend tests belong in `src/__tests__/`. Vitest is not configured with `globals: true` and registers no global `setupFiles`, so every test imports `describe`/`it`/`expect`/`vi` from `"vitest"` explicitly, and every DOM test additionally imports `src/test/setup.ts` — that module is what registers `afterEach(cleanup)` and the jsdom polyfills.
- Frontend tests share module-level singletons; reset them in `beforeEach` with `fakeIpc.reset()`, `resetStores()`, and `resetLaunchRefresh()`. Omitting the last one inherits an already-armed or already-consumed launch-refresh one-shot from a prior case and produces order-dependent flakes.
- Cover relevant success, failure, cancellation/concurrency, stale-state, and contract edge cases. A manager refresh failure must retain its prior snapshot.
- Frontend gates: `npm test`, `npx tsc --noEmit`, and `npm run build`. Browser end-to-end tests are a separate required CI gate: `npm run test:e2e` (Chromium + WebKit) and `npm run test:e2e:typecheck`. Those last two are the only gates that see `tests/` at all.
- End-to-end tests live under `tests/e2e/*.spec.ts` with helpers in `tests/support/`. Import `test` and `expect` from `tests/support/fixtures`, never from `@playwright/test`. That fixture installs an in-browser Tauri IPC double via `page.addInitScript` and throws on an unregistered command — register a response rather than weakening it. It fails a test on any HTTP status >= 400 unless the test already failed or carries a `skipNetworkMonitoring` annotation (the supported opt-out). Its cross-origin block is installed only when `ALLOW_REMOTE_E2E` is unset — setting that variable removes network isolation entirely, not just the config-load guard. Seed data comes from `@faker-js/faker` factories keyed by the test's title path, so renaming a test changes its data. No fixed sleeps.
- `tests/e2e/browser-style-contract.spec.ts` is where the design system is enforced: it pins computed `theme.css` token values as literal `rgb()` strings and asserts focus is a real `outline` (`solid`, `2px`, `rgb(244, 247, 251)`) with a negative guard that it is **not** the accent. Focus assertions must be keyboard-driven — a pointer click sets `:focus` but not `:focus-visible`, so the indicator under test would never be drawn.
- That spec proves the focus mechanism on **two named samples, not a sweep**: a toolbar `<button>` and the package-row checkbox, chosen because they sit on opposite sides of the `appearance` discriminator. It does not enumerate every interactive element. Never read a green run as proof that a newly added control has a visible focus state — verify that control at runtime. Contrast is likewise sampled, not swept: an uncommitted third test computes the WCAG 2.1 ratio for the primary button only and asserts `>= 4.5`, so every other fill in the app remains a by-eye check.
- A WebKit-only e2e failure is authoritative product signal, because the app ships in WKWebView; never dismiss one as a browser quirk. The inverse also holds: CI's `webkit` project is Playwright's **Linux** WebKit on `ubuntu-latest`, not WKWebView, so it is the closest available proxy and not evidence about the packaged macOS app. Real-WKWebView verification remains the manual keyboard-and-VoiceOver pass in `docs/RELEASE-CHECKLIST.md`.
- The Playwright workflow (`.github/workflows/test.yml`) runs typecheck plus `--list` discovery, two sharded Chromium/WebKit runs with `--fail-on-flaky-tests`, and a PR/weekly burn-in (`--repeat-each=10 --retries=0`); a final gate job re-checks upstream results. The report job hard-fails unless exactly two blob reports arrive, so changing the shard count means changing that check too. This e2e Tauri double is distinct from the Vitest `bridge.ts`/`fakeIpc` seam.
- `playwright.config.ts` throws at config load on a non-loopback `BASE_URL` unless `ALLOW_REMOTE_E2E=1`, but it auto-starts Vite only when the resolved origin is exactly `http://127.0.0.1:1420`. Other loopback hosts (`http://localhost:1420`) pass the guard and get no `webServer` — you must start the dev server yourself.
- Rust gates from `src-tauri/`: `cargo fmt --check`, `cargo clippy --all-targets -- -D warnings`, and `cargo test --locked`.
- There are 11 `#[ignore]` Rust tests and none run in CI: two in `src-tauri/tests/live_smoke.rs`, seven in `process/runner.rs`, two in `paths.rs`. Only the `live_smoke.rs` pair assumes a provisioned machine — but the ignored set is not fully machine-independent either: `paths.rs` `real_login_shell_probe_returns_entries` spawns the developer's `$SHELL` (fallback `/bin/zsh`, `paths.rs:106`), so it reads real dotfiles. The rest spawn only `/bin/sh` and `/bin/sleep`.
- **Three** real-process tests are deliberately NOT `#[ignore]` and must stay default-run — each is the only guard on its invariant: `runner.rs` `real_cancel_escalates_to_sigkill_when_term_ignored` (SIGTERM→grace→SIGKILL escalation) and `real_completes_when_descendant_holds_pipes_open_after_exit` (bounded post-exit EOF grace), plus `paths.rs` `probe_timeout_kills_profile_spawned_descendants`, marked "Regression (default-run, /bin/sh only)", which guards that the login-shell probe kills its whole process group so a backgrounded profile child cannot leak to launchd on every launch.
- Surfaced conflict: `live_smoke.rs` still declares this machine as "mas absent" and `dev/fixtures/README.md:92` still says "mas is not installed here", but the same README records mas 7.0.0 installed with real 2026-07-22 captures and D23a withdrew the mas UNVERIFIED label. Treat the "mas absent" precondition as stale, not as evidence of a code defect.

### Code Quality & Style Rules

- Resolve guidance by role: `AGENTS.md` (byte-identical to `CLAUDE.md`) governs release and versioning workflow; `docs/SPEC.md` governs product behavior; a later explicit `docs/DECISIONS.md` entry overrides an earlier decision; `docs/RELEASE-CHECKLIST.md` governs release readiness after D33 retired the formal gate; `ARCHITECTURE-SPINE.md` (`_bmad-output/planning-artifacts/architecture/architecture-Pack-Manager-2026-07-23/`, revision 9) is the **sole authority for architecture invariants and `AD-` ids**; manifests, lockfiles, workflows, and production registration define current mechanics; fixtures/tests support claims only within their documented provenance. Treat `docs/IMPL_PLAN.md` as history, treat nothing under `_bmad-output/archive/` as authoritative, and surface any conflict these rules do not resolve.
- `AD-` ids collide across documents and the spine always wins. `epics.md` retired its own competing AD-1..AD-15 numbering into stubs that point at the spine, but the retired ids are still legible there and mean different things — `epics.md`'s AD-1 was a readiness-concern rule while the spine's AD-1 is "dependencies point inward". Cite an `AD-` only from the spine. `AD-6..AD-10` and `AD-13..AD-15` are retired ids that are **never reused**; live ids are AD-1..AD-5, AD-11, AD-12, and AD-16..AD-27. Inside the architecture run folder, only `ARCHITECTURE-SPINE.md` is current: the 18 `reviews/*.md` lens reports and the 774-line `DRIFT-NOTE.md` are per-revision process residue against superseded revisions, useful as rationale and never as the rule.
- All of `docs/SPEC.md`'s update-experience text is D27–D30 TARGET state, not shipping behavior. §0.1 supersedes conflicting older text below it, but §0.1 is itself undelivered; and SPEC §0 invariant 7 (line 19, ABOVE §0.1) states the unimplemented durable `planAttemptId` in present tense under a "violations are bugs" heading. Resolve Current vs Target from the rules below before assuming `planAttemptId`, `Verifying`, `InteractionRequired`, or the separate confirmation dialog exists.
- Keep Tauri command handlers thin. Put orchestration in focused Rust modules, manager behavior in adapters, and pure parsers under `src-tauri/src/managers/parse/` — parsers never log and never touch the clock, filesystem, or a process. Testability enforces this independently of layering taste: a `#[tauri::command]` taking `tauri::AppHandle` cannot be unit-tested because a test cannot construct one, which is exactly why `refuse_app_update_while_busy` was split out of `install_app_update`.
- Components and component files use PascalCase; hooks use `useX`; Zustand stores use `useXStore`; helpers use lower camelCase; constants use uppercase names. Follow surrounding Rust naming and module conventions.
- There is no configured Prettier or ESLint script. Match surrounding TypeScript/Markdown formatting; run `cargo fmt` on modified Rust before committing.
- Reuse existing primitives, stores, adapters, error mappings, and nondeterminism seams before introducing a new abstraction.
- Treat `queue.rs`, `process/runner.rs`, `ops.rs`, IPC types, persistence, diagnostics, and updater installation as high-risk trust boundaries requiring focused tests and review.

### Development Workflow Rules

- Preserve unrelated working-tree changes and read configuration files before editing them.
- Use conventional commits: `fix:` triggers a patch, `feat:` a minor, and `feat!:` or `BREAKING CHANGE:` a major release. `chore:`, `docs:`, `ci:`, `refactor:`, and `test:` do not trigger a release alone.
- Never manually edit versions in `package.json`, `package-lock.json`, `src-tauri/tauri.conf.json`, `src-tauri/Cargo.toml`, or `src-tauri/Cargo.lock`. Do not edit `CHANGELOG.md` or `.release-please-manifest.json`; release-please owns all seven files.
- A releasable commit reaching `main` enters release automation with no later human gate: release-please opens the release PR, the workflow squash-merges it automatically, and the signed, notarized artifacts publish. Keep work off `main` until it is ready to ship.
- Two release-workflow mechanics look like redundancy and are not. The release PR must be SQUASH-merged: a merge commit repeats the original commit message in its body, so release-please counts the same fix twice (it already did across 0.2.0–0.2.3). And `release-please-action` is invoked twice inside one job because pushes made with `GITHUB_TOKEN` do not trigger other workflows, so the auto-merge would never re-run the workflow and the tag would never be cut.
- A manual Release run publishes nothing only when `attach_to_tag` is EMPTY — then artifacts go to the workflow run alone. A manual run with `attach_to_tag` set to an existing tag checks out the source at that tag and uploads to that GitHub Release with `--clobber`. Both release-upload paths key off `inputs.attach_to_tag != ''`, not the trigger event.
- `npm run tauri build` fails locally without the updater signing key: `plugins.updater.pubkey` is set, so the CLI refuses to bundle with no matching `TAURI_SIGNING_PRIVATE_KEY`, and a mismatched throwaway key is rejected too. Build unsigned with `-- --no-sign` (what CI's build-smoke does), or signed with `fnox exec -- npm run tauri build`.
- Action pinning is per-workflow, not repo-wide: `release.yml` and `test.yml` pin every third-party action to a 40-char commit SHA with a version comment, while `ci.yml`, `release-please.yml`, `claude.yml`, and `claude-code-review.yml` use floating tags — `release-please.yml` floats `googleapis/release-please-action@v5` twice despite holding `contents`/`pull-requests`/`actions: write` and `secrets: inherit`, so credential-bearing does not imply SHA-pinned. Match the file you are editing; never introduce a floating tag into `release.yml`.
- `**/.memlog.md` is deliberately **tracked**, not ignored (the ignore line was removed in `c8c1f9a`). A memlog is a BMAD run's append-only working memory — `_bmad/scripts/memlog.py` has no edit or delete subcommand by design — and the `Update` intents resume from it as the authority on what was decided, not from the rendered artifact. It is not a deliverable and it is not regenerable: delete one and its artifact can never be re-distilled. Never rewrite, prune, or `.gitignore` a memlog.
- The working tree gains and loses files mid-session from concurrent BMAD workflows (scan reports rotating into the gitignored `docs/.archive/`, run folders appearing under `_bmad-output/`). Stage by explicit path; never `git add -A`.
- Accessibility coverage is split and knowing which half is which prevents both wasted work and false confidence. ### Critical Don't-Miss Rules

- The package manager's `outdated` verdict is authoritative. Version-delta logic lives in `src/lib/versionDelta.ts`, is display-only, and must never decide whether an update exists — real data includes `2.0.14-1`, `1.6.2.dev0`, `stable`, and rustup commit hashes, on which semver math produces wrong verdicts.
- Exactly six managers are supported (brew, mise, npm, uv, rustup, mas); `ManagerId::ALL` is the registry and defines canonical ordering. `ManagedBy` is a different, four-variant set (brew, mise, rustup, standalone).
- Derive manager ownership and self-update routing from detected paths. Classify the raw path against mise's shims/installs directories BEFORE canonicalizing it; mise shims are symlinks to the mise binary, so canonicalizing first misroutes npm/uv to brew. Route precedence is fixed: in-band override → delegated-if-detected → native → unavailable.
- Two path rules invert each other and both are load-bearing. `paths.rs` `static_entries` is order-sensitive: mise's shims directory stays FIRST, ahead of `/opt/homebrew/bin`, so uv/npm/node resolve to shims rather than brew binaries — do not sort the list or hoist Homebrew. But `resolve_binary` applies a shim-vs-own-tree preference for MANAGER binaries only: when the `which` hit is a mise shim and that manager has a real install in its own tree (rustup at `~/.cargo/bin`), the real binary wins. It can never reroute a manager into another manager's tree, and simplifying it to a bare `which` lookup misclassifies standalone rustup as mise-managed.
- `refresh_all` and the header Refresh must re-run detection FIRST (rebuild `ToolEnv`, `detect_all`, store, emit `detection:updated`) and build the fan-out from FRESH statuses, never the cached `DetectionOutcome`; `refresh_manager` re-probes a manager the cached detection marks absent instead of erroring `tool_not_found`. Reading the already-populated cached detection reintroduces a fixed, named bug: `brew install mas` then Refresh All left mas "Not installed" with no refresh enqueued.
- **Target (D27, not yet implemented):** every Package and Manager update enters one persistent Upgrade Plan, and no row, Manager header, selection, or Update Everything action executes immediately. **Current:** the Upgrade Plan is transient dialog state (`ui.dialog` `{ kind: "upgradePlan" }`, discarded by `closeDialog`), and `ManagerPane.upgradeRow` builds a single-package plan and calls `executePlan` immediately with no sheet — that is unscheduled D27 work, not a bug to fix in passing. Either way, store the canonical `PlanRequest`/`PlanIntent`, not executable display strings. Before preview issuance, canonicalize explicit Package identities (`queue.rs` `canonicalize_plan_request`): preserve `null`, enforce the 2,048-entry / 512-byte-ID bounds, and remove exact Manager/Package duplicates first-seen-order. Manager self-updates are **currently** a single global all-or-nothing `include_self_updates` toggle; the target replaces it with independent removable membership — do not re-entrench a global toggle when implementing this.
- Keep the one-use preview `planId` separate from the durable coherence token. At most 64 unconsumed plan capabilities are retained per session (`ISSUED_PLAN_LIMIT`, oldest-first eviction); an evicted `planId` must fail closed exactly like an unknown or already-replayed one — never add a fallback that reissues, revives, or leniently accepts one. Execution must exactly match the issued preview and a fresh coherent rebuild, and must reject an in-progress state update, revision drift, an active refresh, or a lock-set overlap with any pending/running Upgrade/SelfUpdate/HealthFix (`queue.rs` `has_existing_mutating_lock_conflict` → `PlanBatchError::MutatingOperationConflict`), submitting only re-derived groups through atomic all-or-none admission (`commands.rs` `execute_issued_plan`, `queue.rs` `submit_plan_batch`). That is a lock-overlap check, not a global one-attempt-at-a-time rule. **Current:** the durable token is a monotonic `revision`/epoch in `PlanCoordinator`; `OperationRecord` carries no plan-attempt id, and no "attempt" concept exists in the Rust source. **Target (D27–D30, not yet implemented):** a durable `planAttemptId` that Events, Operations, transcripts, journal records, verification, Results, History, diagnostics, and Retry lineage all carry, with one confirmed attempt active at a time. Never fabricate plan grouping for legacy Operation records.
- **Current:** confirming the plan calls `executePlan(plan)` directly from the Upgrade Plan sheet — there is no separate final-confirmation dialog and no `skipUpgradePlanConfirmation` setting, and `autoOpenDrawer` is an **active** setting consumed in `useOperationEffects.ts`. A failed `execute_plan` other than `plan_stale` must not be retried speculatively, because the one-use capability may already have been consumed. **Target (D27–D30, not yet implemented):** `Confirm N updates` opens a separate final confirmation dialog whose skip-future checkbox persists `skipUpgradePlanConfirmation` (default `false`), and `autoOpenDrawer` becomes inactive legacy input. Skipping the dialog must never skip draft review, Rust rebuild, or stale-plan validation.
- The single scheduler atomically checks and acquires each operation's complete lock set before start — one tokio task owns pending/held/running, so no ordered acquisition is needed and no deadlock is possible. The lock set is {executor} ∪ {subject}, plus the Mise lock when a mise-managed npm or uv is the executor. Preserve the global concurrency cap of 4, the 120s aging guard that disables skip-ahead, and duplicate-refresh coalescing — which returns the existing opId, creates no record, emits no event, and does not bump the revision.
- Plan building applies rust-dedup (D10): when rustup contributes any included package, mise's `tool:rust` is removed and re-emitted as an `ExcludedPackage` with `ExcludeReason::RustDedup` plus the `RUST_DEDUP_NOTE`. One plan never contains both mise `tool:rust` and rustup toolchains. Do not drop this as unexplained special-casing.
- Never run shell command strings. Spawn resolved absolute executables with structured argv, `env_clear`, an explicit environment, null stdin, and `process_group(0)`. Self-update and health-fix argv stays backend-only via `#[serde(skip)]`; derive previews from argv, never split display text back into arguments, and fail closed when a submitted preview does not match the preview re-rendered from trusted argv. No sudo or password prompt path is allowed.
- Add `HOMEBREW_NO_AUTO_UPDATE=1` to every Brew command except the explicit `brew update` operation. It is deliberately absent from the constructed base environment, so it must arrive through per-command `extra_env`. Do not automatically retry external Homebrew lock contention.
- One manager failure must not blank other managers or overwrite its previous successful snapshot. `parse_recovery` must MERGE the recovered overlay into the inventory already parsed from the successful refresh outputs — replacing the snapshot with an outdated-only overlay makes every up-to-date package vanish. Merging never un-pins a row.
- A manager-declared expected nonzero exit is not an operation failure; notably, usable npm outdated JSON may exit 1 (classified `ExpectedNonZero` only for `--json` commands) and must reach the parser before error classification. A non-zero `brew update` degrades to stale metadata rather than aborting the refresh. mise, uv, rustup, and mas have no expected-nonzero exits.
- Process-level durability holds today: preserve the process reader's literal unterminated-notice handling (`UNTERMINATED_NOTICES` is a closed list of verbatim strings, never patterns, and a notice sitting at the end of a buffer is left alone) and the bounded 2s post-exit EOF grace, which exists because descendants inherit the pipe write ends — `process_group(0)` isolates signals, not file descriptors. On shutdown, cancel AND await idle before exiting, or the kill tasks may never be polled; never signal journaled PIDs after restart, because PID reuse is unsafe. **Current:** correlation across Operation status/output events, transcripts, structured logs, and the crash journal is by `opId`, and History is the Operation-level `operations.jsonl`. **Target (D27–D30, not yet implemented):** plan status/Results and nested Operation records share a `planAttemptId`, and primary cancellation targets the attempt, skips unstarted work, and preserves every terminal outcome.
- **Current:** an operation is marked `Succeeded` at process exit (`classify_exit`), and a successful Upgrade/SelfUpdate/HealthFix auto-enqueues a refresh of the affected subject and executor as a **separate** operation (`queue.rs`); `OpStatus` has exactly seven variants and there is no `Verifying` status and no per-attempt History or Retry lineage. **Target (D27–D30, not yet implemented):** do not declare success at process exit — enter `Verifying`, refresh every affected subject/executor Manager, and distinguish mutation failure from verification failure in Results; History keeps one immutable row per confirmed attempt and Retry creates a new linked attempt rather than overwriting the first failure.
- **Current:** unknown null-stdin silence follows the ordinary stall path (`op:stalled` / `StallNotify`, `runner.rs`) — the watchdog only notifies and re-arms, and only the runner's hard cap kills — and the UI exposes only `Cancel operation`. **Target (D27–D30, not yet implemented):** show `Interaction required` only when a closed Manager-specific classifier or explicit native signal recognizes a trusted prompt, and make the primary label `Cancel plan` when the remaining attempt is affected, reserving `Cancel operation` for explicitly Operation-scoped diagnostics.
- Settings and journal rewrites remain atomic. Persist a settings patch before publishing it in memory or advancing the canonical revision; a failed save changes neither. Journal-append and structured app-log write failures are nonfatal to package operations, and journal compaction keeps the newest 1,000 records via temp file + fsync + rename because a truncate-in-place interrupted by power loss would destroy the very interrupted records the file exists to surface. Transcript creation failure blocks spawn, while later transcript-write failures are best-effort. Diagnostics must reject symlinks both when selecting and when streaming files.
- Application-update checks and downloads may run in the background, but installation requires an explicit user Restart action, and the app self-update sits deliberately outside the queue/ops model — not an Operation, holds no manager lock, never in History. Only *manual* checks may surface a toast: an automatic check that finds nothing or fails offline must stay invisible, and a repeated payload for the same terminal state must not re-toast. If the bundle parent is not writable, require manual installation rather than triggering an administrator prompt; `app_update.rs` pre-flights with `access(2)` to stop before the plugin's AppleScript admin fallback.
- Refusing an app update while package work is in flight is now enforced in **two** layers and both must stay. The frontend quit guard is the path that explains itself to the user; `install_app_update` (`commands.rs:810`) independently calls `refuse_app_update_while_busy` (`:772`), because the command kills every child via `shutdown()` then `restart()`, so a caller that skips the guard destroys in-flight work and its journal tail. That function's status set mirrors `activeOps` in `src/store/operations.ts` **exactly** — `Queued` counts as active, since admission has already committed to the operation and a restart would drop it unstarted. Change one side's status set and you must change the other.
- **Keyboard focus is the one defect class that greens every suite and still ships broken.** WebKit does not paint `box-shadow` on a control still rendering with its **native appearance** — the discriminator is `appearance`, not the element and not the property, which is why a Tailwind `ring-*` paints on a `<button>` and not at all on `<input type="checkbox">` or `<select>`. This app ships in WKWebView, so a ring on those controls is invisible while `:focus-visible` still matches `true`. Use `outline` + `outline-offset` uniformly; `appearance: none` also makes a ring paint and is rejected because it destroys the native checkmark. A *missing* focus indicator is invisible to source search — the absence of a class is not greppable — and a runtime audit of the real tab order found nine unstyled controls where a grep-based count found three. Walk the tab order and read computed style; do not trust a class-name search.
- Selection must always exclude pinned packages and greedy casks unless the user explicitly opts in — but the packages store does NOT enforce this: `setSelection`/`selectRange` store whatever ids they are given, and callers must filter through `isSelectable` first. Two call sites duplicate that filter chain (`ManagerPane.tsx` and the Cmd+A path in `useKeyboard.ts`) and must change together. Plan-level exclusions carry reasons rather than silently dropping rows. Unknown latest versions remain `null`; never fabricate a version delta. Greedy-only casks are a two-call set difference, never an in-JSON heuristic.
- Re-check self-update routes after every freshly parsed refresh snapshot; a manager's own outdated row can override delegated routing, especially npm inside mise. The manager's own package row is hoisted into `SelfStatus` and never appears in the package table.

Altered, missing, or malformed suggestions remain visible in the warning detail but are neither copyable nor runnable.
